布局决策

  1. 一屏三层:顶部 KPI 给结论、中部趋势图给走势、右侧订单表给可操作项,自上而下由「概览」收束到「行动」(为什么:工作台首屏要三秒定位当天全貌,KPI 引导注意力、订单承接操作,层级不交叉)。
  2. 时间范围切换 = 换数据注册表的 key:KPI 与图柱同源,经单一 render() 整体重绘(为什么:数据同源只改 range key,杜绝 KPI 与图表不同步的中间态;行为类改动只进 JS)。
  3. 图柱用纯 CSS 高度占比:柱高 = value/max,点柱把数值写进 tooltip 行而非悬浮浮层(为什么:零依赖零遮挡,行内提示在密集面板里不易盖住相邻数据)。
  4. 状态筛选用可见 chips 而非下拉:全部/待付款/待发货/已付款/已完成 直接外露(为什么:后台高频筛选,选项可见可一眼点选,省一次展开动作)。
  5. 配色为演示令牌:整套演示稿统一「星云工作台」令牌,接入真实项目时替换 :root B 段(待确认)。
